# Практика: типы в знакомом React-магазине

В аудитории — три шага по пять минут. Работайте с небольшим компонентом из своего магазина, а не переводите весь проект за один раз. Эталон для сверки после попытки: `examples/BookCatalog.tsx` и `examples/PriceEditor.tsx`. Они запускаются в демо лекции без сервера API.

## Шаг 1. Модель данных

1. Создайте `Book`: строковые id, title, author и числовой price.
2. Получите `BookPreview` через `Pick`: только id/title/price для короткой карточки.
3. Получите `NewBook` через `Omit`: данные новой книги без id.
4. Опишите `Cart` через `Record<string, number>`: id книги → количество. Учитывайте отсутствующий ключ через `?? 0`.

Проверка: строковая цена должна дать ошибку TS. Изменение типа через Pick/Omit само не меняет реальный объект.

## Шаг 2. Компонент и состояние

1. Файл с JSX переименуйте в `.tsx`.
2. Опишите props карточки: `book: BookPreview` и `onAdd: (id: string) => void`.
3. Типизируйте список как `useState<Book[]>([])`, выбор — как `useState<Book | null>(null)`.
4. Простой счётчик оставьте `useState(0)`: тип уже выводится.

Проверка: `onAdd(book.price)` и `setCount("2")` должны дать ошибки. Затем исправьте их. Для выбранной книги учтите null перед чтением полей.

## Шаг 3. Форма изменения цены

1. Черновик input храните строкой: пользователь может очистить поле.
2. Вынесенный обработчик изменения типизируйте `ChangeEvent<HTMLInputElement>` из react.
3. При сохранении проверьте пустоту, преобразуйте через Number и проверьте конечность и неотрицательность.
4. Передайте результат обработчику `(id: string, price: number) => void`.

Проверка: пустая и отрицательная цена не сохраняются, корректная обновляет карточку. Тип события не выполняет проверку бизнес-правил вместо JavaScript.

## Что ещё попробовать после занятия

- Дать children панели тип ReactNode.
- Переиспользовать стандартные props кнопки через ComponentProps<"button">.
- Добавить useRef<HTMLInputElement>(null) и кнопку фокусировки на поле.
- Назвать тип результата своего хука выбора книги.
- Получить значение как unknown и проверить typeof перед использованием. any не считать проверкой внешних данных.

Готово, когда tsc проходит, понятны несколько намеренных ошибок и интерфейс работает как прежде. Сложные дженерики, keyof и never не обязательны для этой практики; они сохранены в `docs/extra-topics.md`.
